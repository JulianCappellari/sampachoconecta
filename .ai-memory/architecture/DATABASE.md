## Persistencia y esquema

[db.ts](../../web/src/lib/db.ts) usa pg, DATABASE_URL, pool global de hasta 5 conexiones, TimeZone UTC y parsers int8/numeric a number. No hay SQLite en el runtime de la app. Los timestamps de negocio siguen como TEXT UTC YYYY-MM-DD HH:MM:SS. El SQLite anterior permanece intacto y gitignored.

[schema.ts](../../web/src/lib/schema.ts) conserva migraciones 1–4 y constraints; IDs GENERATED BY DEFAULT AS IDENTITY, REAL convertido a DOUBLE PRECISION y email CITEXT UNIQUE. Extensión citext y funciones datetime/julianday en [sql.ts](../../web/src/lib/sql.ts); estas fijan UTC internamente. Migraciones en transacción con advisory lock. Cada proceso comprueba schema_migrations una vez y migra si falta algo. También se ejecutan explícitamente mediante db:migrate.

## Contratos e invariantes

- all/one/run/tx son async; consultas parametrizadas. translate convierte placeholders anónimos/numerados, LIKE e INSERT OR IGNORE sin tocar literales/comentarios. run informa changes/id y agrega RETURNING id solo donde corresponde.
- tx usa AsyncLocalStorage y un cliente; consultas secuenciales; SAVEPOINTs anidados. SERIALIZABLE con reintentos acotados para 40001/40P01. No ubicar llamadas de red o almacenamiento dentro de callbacks que puedan reintentarse.
- Reclamos/historial: triggers bloquean DELETE y TRUNCATE. El reset deliberado del script usa SET LOCAL sampacho.allow_reset='on'; la app no lo activa. No es barrera contra el dueño de la base.
- Versiones y UPDATE condicionales evitan ediciones perdidas. Avisos conservan una marca temporal monotónica incluso dentro del mismo segundo. Cupos se revalidan en transacción. UNIQUE evita duplicados de votos, opiniones, respuestas y event_key de notificaciones.
- El límite de ingreso vive en kv con clave hash y un upsert atómico: ocho intentos por diez minutos, compartidos entre instancias. El envío push posterior a la respuesta sale del scope de transacción antes de consultar.
